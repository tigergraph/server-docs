= Load from Apache Iceberg

In version *4.3*, TigerGraph introduces a connector to load data from an *Apache Iceberg*. This connector allows you to load data stored in *AWS S3* or *MinIO* buckets that are managed by an *Iceberg REST Catalog*.

This guide shows how to connect your data source, create a loading job, and manage it effectively.

== Build Your Graph Foundation

Start by defining your graph schema in TigerGraph. This specifies vertex types (like person or post) and edge types (like friend or posted).
Here’s a simple social network example:

[source,gsql]
.Sample social network schema
----
CREATE VERTEX person (PRIMARY_ID personId STRING, id STRING, gender STRING) WITH STATS="OUTDEGREE_BY_EDGETYPE"
CREATE UNDIRECTED EDGE friend (FROM person, TO person)
CREATE VERTEX post (PRIMARY_ID postId UINT, subject STRING, postTime DATETIME)
CREATE DIRECTED EDGE posted (FROM person, TO post)
CREATE DIRECTED EDGE liked (FROM person, TO post, actionTime DATETIME)
----

Adjust your schema as required for your data.

== Connect Your Data Source

Configure a data source object to connect TigerGraph to your Apache Iceberg storage (S3 or MinIO). This involves specifying connection details using JSON.

=== Format Your Strings
Use double quotes ("), triple double quotes ("""), or triple single quotes (''') for JSON. Quotes can be omitted for simple JSON without colons or commas.

=== Iceberg Setup Basics
Configure these key settings:

[cols="1,2,1",options="header"]
|===
| Configuration Property
| Description
| Required

| type
| Set to "iceberg" for Iceberg
| Yes

| iceberg.catalog.type
| Use "rest" as the catalog type
| Yes

| iceberg.catalog.uri
| Enter the catalog endpoint (e.g., http://ip:port)
| Yes

| iceberg.snapshot.id
| Select a specific snapshot (optional, uses latest by default)
| No
|===

=== MinIO Example
Connect to MinIO with a REST catalog:

[source,gsql]
CREATE DATA_SOURCE s1 = """
{
    type: iceberg,
    iceberg.catalog.type: rest,
    iceberg.catalog.uri: http://rest:8181,
    aws.s3.endpoint: http://minio:9000,
    aws.s3.access_key: accesskey,
    aws.s3.secret_key: password,
    aws.client.region: us-east-1
}""" FOR GRAPH socialNet

=== S3 Example
Connect to an S3 bucket:

[source,gsql]
CREATE DATA_SOURCE s1 = """
{
    type: iceberg,
    iceberg.catalog.type: rest,
    iceberg.catalog.uri: http://localhost:8181,
    aws.s3.warehouse: s3://bucket-containing-iceberg-tables/,
    aws.s3.access_key: accesskey,
    aws.s3.secret_key: password,
    aws.client.region: us-west-1
}""" FOR GRAPH socialNet

== Set Up Your Loading Job

Create a loading job to turn Iceberg data into your graph’s vertices and edges. It involves defining data sources and mapping the data.

=== Quick Loading Job Example
Load social network data with filters to save time:

[source,gsql]
CREATE LOADING JOB loadSocialNet FOR GRAPH socialNet {
  DEFINE FILENAME f1 = "$s1:SELECT personId, id, gender FROM iceberg_connector.person WHERE gender = 'male'";
  DEFINE FILENAME f2 = "$s1:SELECT fromF, toF FROM iceberg_connector.friend";
  DEFINE FILENAME f3 = "$s1:SELECT postId, subject, postTime FROM iceberg_connector.post WHERE postId > 50";
  DEFINE FILENAME f4 = "$s1:SELECT fromP, toP FROM iceberg_connector.posted";
  DEFINE FILENAME f5 = "$s1:SELECT fromL, toL, actionTime FROM iceberg_connector.liked";
  LOAD f1 TO VERTEX person VALUES ($0, $1, $2);
  LOAD f2 TO EDGE friend VALUES ($0, $1);
  LOAD f3 TO VERTEX post VALUES ($0, $1, $2);
  LOAD f4 TO EDGE posted VALUES ($0, $1);
  LOAD f5 TO EDGE liked VALUES ($0, $1, $2);
}

=== Boost Performance
- *2 Tasks from Data Source*: Use 2 tasks for smaller datasets.
[source,gsql]
CREATE DATA_SOURCE s1 = """
{
  type: iceberg,
  iceberg.catalog.type: rest,
  iceberg.catalog.uri: http://rest:8181,
  aws.s3.endpoint: http://minio:9002,
  aws.s3.access_key: admin,
  aws.s3.secret_key: password,
  aws.client.region: us-east-1,
  tasks.max: 2
}""" FOR GRAPH socialNet
CREATE LOADING JOB loadPersonIceberg FOR GRAPH socialNet {
  DEFINE FILENAME f1 = "$s1:SELECT personId, id, gender FROM iceberg_connector.person WHERE id = 'John Doe'";
  LOAD f1 TO VERTEX person VALUES ($0, $1, $2);
}

- *8 Tasks from Job*: Use 8 tasks for larger data.
[source,gsql]
CREATE DATA_SOURCE s1 = """
{
  type: iceberg,
  iceberg.catalog.type: rest,
  iceberg.catalog.uri: http://rest:8181,
  aws.s3.endpoint: http://minio:9002,
  aws.s3.access_key: admin,
  aws.s3.secret_key: password,
  aws.client.region: us-east-1
}""" FOR GRAPH socialNet
CREATE LOADING JOB loadPersonIceberg FOR GRAPH socialNet {
  DEFINE FILENAME f1 = "$s1:{query: 'SELECT personId, id, gender FROM iceberg_connector.person WHERE id = 'John Doe'', tasks.max: 8}";
  LOAD f1 TO VERTEX person VALUES ($0, $1, $2);
}

== Define Your Data Files

Set up filenames to point to your Iceberg data using SQL queries.

=== Query Your Data
Use a query, config file, or inline JSON. Examples:

[source,gsql]
DEFINE FILENAME query_person = "$s1:SELECT personId, id, gender FROM iceberg_connector.person";
DEFINE FILENAME bq_inline_json = "$s1:myfile.json";
DEFINE FILENAME query_person = "$s1:{query: 'SELECT personId, id, gender FROM iceberg_connector.person WHERE gender = 'male'', tasks.max: 2}";

=== File Settings
[cols="1,2,1,1",options="header"]
|===
| Configuration Property
| Description
| Required
| Default

| query
| SQL query to fetch your data
| Yes
| None

| tasks.max
| Number of parallel tasks
| No
| 1

| batch.size
| Rows per batch
| No
| 3000
|===

== Map Data to Your Graph

Use LOAD statements to map Iceberg query result fields to graph schema attributes.

Match columns with a separator like "|". Example:
[source,gsql]
LOAD f1 TO VERTEX person VALUES ($0, $1, $2) USING separator="|";

$0, $1, $2 represent the first, second, and third columns. Add transformations like SPLIT if needed.

== Start the Loading Process

Run your loading job with the `RUN LOADING JOB` command and monitor progress.

=== Run with Flexible Filenames
Update filenames at runtime for convenience. Example:
[source,gsql]
RUN LOADING JOB loadPerson USING f1="$s1:SELECT personId, id, gender FROM iceberg_connector.person WHERE gender = 'female'"

=== Continuous Loading
- One-time load with `EOF="true"` (default).
- Ongoing load with `EOF="false"` and optional `poll.interval.ms` to reload periodically until stopped.

== Monitor and Control Your Job

Track and manage your job with these commands:

[source,gsql]
SHOW LOADING STATUS ALL
ABORT LOADING JOB job_id
RESUME LOADING JOB job_id
SHOW LOADING ERROR job_id

Check progress with `SHOW LOADING STATUS`. Stop or restart jobs as needed.

=== Manage Multiple Jobs
See xref:loading-concurrency.adoc[Loading Job Concurrency] for how to manage the concurrency of loading jobs.

== Common Challenges

* TigerGraph does not store NULL values. Input data should not contain any NULLs.
* Authentication for REST Catalogs isn’t supported in TigerGraph 4.3
